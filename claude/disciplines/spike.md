# Spike

When the plan picks this: a time-boxed question about feasibility or approach where the answer matters more than the code. Output is a finding, and the code is thrown away.

## Rules
- State the question and the decision it informs before starting. A spike that informs no decision does not run.
- Set the box in the plan (hours or number of attempts) and write it at the top of the notes.
- Work on a scratch branch or copy. Nothing from it merges.
- Prefer the cheapest experiment that can say no.
- Record what was tried, what each attempt showed and the numbers, as facts with the command that produced them.
- Name the next step if the answer is yes, and what it would cost.

## Proof
The finding answers the question with evidence a reader can rerun.

## Stop
The question is answered, or the box runs out. At the box limit report what is known and what is not, and do not extend it on your own.
